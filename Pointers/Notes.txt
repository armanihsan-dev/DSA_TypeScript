PART 1: What ARE Pointers? (Language Agnostic)
The Definition
A pointer is a variable that stores the memory address of another variable, not the value itself.

The Analogy
Regular variable: Your home address = "123 Main St" (the actual house)

Pointer: A sticky note that says "look at 123 Main St" (directions to the house)

Why Pointers Exist
Efficiency - Pass address (8 bytes) instead of copying entire data (could be MBs)

Sharing - Multiple things can point to the same data

Dynamic memory - Create things on the fly, not just at start

Visual Example
text
Regular Variable:     x = 42
                      [x] ---> 42 (direct)

Pointer:              ptr = &x  ("&" means "address of")
                      [ptr] ---> [x] ---> 42 (indirect)

                      ptr doesn't hold 42
                      ptr holds the LOCATION of 42


PART 2: How TypeScript Handles This (No Real Pointers)
The Hard Truth
TypeScript/JavaScript has NO memory addresses and NO pointer arithmetic.

But you can achieve the same BEHAVIORS using references.

Behavior 1: Sharing Data (Multiple things pointing to same object)
How TypeScript does it:

typescript
let x = { value: 10 };
let ref1 = x;  // Not a pointer, but behaves like one
let ref2 = x;
ref1.value = 20;
console.log(ref2.value); // 20 ✅ Same effect!
The Rule: Objects are shared by reference automatically. Arrays, objects, functions - all work this way


Behavior 2: Modifying Primitives (Numbers, Strings, Booleans)
// Behavior 2: Modifying Primitives (Numbers, Strings, Booleans)

// let num: number = 10;
// function increment(val:number){
//     val++ //  // Only changes COPY
//     console.log(val)
// }
// increment(num)
//console.log(num) // num is STILL 10 ❌
// because JavaScript (and TypeScript) always passes primitives(string, numbers, boolean, undefined, null) by value, but passes non-premitives(object,arrays,function)  by reference.

//solution in ts: wrap in an object
interface myNumShape {
  value: number;
}
let myNum: myNumShape = { value: 10 };
function increment(obj: myNumShape) {
  obj.value++;
  console.log(obj.value);
}
increment(myNum);
console.log(myNum);

// Behavior 3: Null/No Object (The "Null Pointer")
let nullObj: { value: number } | null = null;
function handleNullPointer(obj: { value: number } | null) {
  if (obj == null) {
    console.log('Null pointer detected! Cannot access properties of null.');
  }
}
handleNullPointer(nullObj);

Mental Model for TypeScript Developers
Stop thinking about memory addresses. Think about references instead.

// In TypeScript, you write:
let ref = x;       // ref REFERS TO x
ref.value = 20;    // Change whatever ref refers TO
ref.field          // Access field of what ref refers TO


The 3 Rules You Need
Rule 1: Objects are automatic pointers
typescript
let a = { count: 1 };
let b = a;  // b "points to" same object
a.count = 2;
console.log(b.count); // 2 - sees the change!
Rule 2: Primitives need wrapping
typescript
// Won't work
let a = 1;
let b = a;
a = 2;
console.log(b); // 1 - doesn't see change ❌

// Will work
let a = { value: 1 };
let b = a;
a.value = 2;
console.log(b.value); // 2 - sees change ✅
Rule 3: null is your nullptr
typescript
let maybe: number | null = null;  // Points to nothing
maybe = 42;  // Now points to 42
